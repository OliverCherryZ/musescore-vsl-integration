# 项目目的与功能详解

这个项目希望让“写在谱上的演奏要求”和“第三方音源实际发出的声音”衔接得更直接：在 MuseScore 中编辑奏法、力度和乐句，让原生回放与导出使用同一套明确的播放计划，并减少手工维护切换键的工作。

项目包含两个层次：一层是定制 MuseScore 中可配置的 VST3 奏法映射；另一层是已经围绕 Vienna Synchron Player / Synchron Solo Strings 完成适配的插件、音色目录和加载流程。前者可以供其他兼容 VST3 音源使用或扩展，后者依赖特定播放器与预设结构。

## 开发从什么问题出发

**谱面记号与音库命令之间有距离。** MuseScore 本来就能加载 VST3 音源并播放音符，但不同音库切换长音、短音、拨弦、连奏的方式各不相同。有的需要一个键位，有的需要按次序选择多个维度，有的还需要设置控制器。谱上同样写 `pizz.`，音库并不会因此自动知道应触发哪个按钮或采样。

**手工控制信息容易与作品脱节。** 若需要另外插入切换音、维护隐藏控制谱表，或先运行同步脚本，再去播放或导出，用户每次改谱都要兼顾两套内容。删除一个记号、调整反复、从中段起播后，旧的控制状态也可能影响后面的声音。项目因此把受支持的记谱语义放进原生播放链，在生成音乐事件时同时生成音源选择命令。

**动态控制需要保持可写、可听、可导出。** 单音动态和渐强渐弱是写作中常用的表达手段。针对本次 Synchron 工作流，项目保留这些宿主控制，并用专用的原始音频参考识别宿主增益变化，将突然跳变衔接成短时间内的连续过渡。平滑对象是增益曲线；音符起音时间、采样本身的音头和自然包络仍由宿主与音源决定。

**播放正常也需要能稳定导出。** 第三方播放器在实时和离线处理时可能采用不同状态，新选择的采样也可能尚在载入。项目把音源准备接入播放与原生音频导出的入口，并为 Synchron 包装层处理对应的处理模式交接。使用者仍从 MuseScore 正常播放或导出，不需要另设一条录音工具链。

## 通用奏法映射怎样工作

正常的音乐音符与音源控制命令是两类信息。定制宿主保留音乐音符的音高和记谱时值，同时把受支持的持续奏法、局部符号以及真实震音／颤音展开来源交给映射层。映射按“插件标识 + 乐器标识”明确匹配，选定路线后，在相应音乐音符起音前发出控制指令。

例如，匹配配置可以把 `pizz.` 解释为某条拨弦路线，保持这一状态，直到后续 `arco` 恢复普通拉弦。断奏点等局部符号按对应音或乐句处理，不必在每个音后再补一次恢复标记。具体优先级、组合和回退由当前支持的规则与配置决定。

这带来几个直接的使用结果：

- 不必为了切换音色在作品中增加可见或隐藏的控制音，也不占用某个声部。
- 已提交的标记修改会用于后续回放与原生导出；插入、删除和撤销等编辑不需要用户再手动同步一次。这里的“提交”指完成一次编辑，不是每敲一个文字就立即改变正在播放的声音。
- 同一时刻的控制命令与音乐起音有明确顺序，不依赖切换键音高碰巧排在音乐音符前面。
- 配置可处理持续状态、局部奏法和已展开装饰音的不同要求。跳播、重启播放及反复相关的状态行为有对应回归用例；复杂的新作品仍需实际核对。

### 表达映射能配置到什么程度

当前 JSON 映射按目标资源、乐器和路线配置，支持：

- 每条路线 **1–16 个 MIDI 切换键**，以及配置的 MIDI 通道和切换键力度。
- 路线附带的 **离散 MIDI CC 值**，控制器编号和值均为 0–127；目标 VST3 必须提供相应的 `IMidiMapping` 映射。
- 符号、准确奏法文字、优先级、部分组合规则、默认路线及必要的回退。

当前 schema 的路线仍以切换键为基础，CC 是可选附带命令。它不提供独立的纯 CC 路线、可绘制的连续 CC 曲线、自动识别所有音库的机制，也没有随包提供所有厂商的预制映射。适合现有规则的音库可以通过修改 JSON 适配，无需重新编译宿主；需要其他控制协议或复杂新语义的音库仍可能需要开发。

默认映射只匹配已配置的 Synchron 资源。没有匹配映射的普通 VST3 不会收到这套额外切换键。定制宿主对部分准确奏法文字增加了记谱语义识别，因此它们可能同时影响其他音源原本已有的时值或力度解释；任意说明句、歌词和未知文字不会被猜测成音色命令。

## Synchron 适配具体提供了什么

### 更容易选择具体音色

VSL Articulations 选择器可按关键词和类别等条件查找音色。谱面使用简短的英文／意大利语标记，完整路径保留在详情中，精确路线通过隐藏字段保存。这样既能保持谱面可读，也能区分多个短名称相同的音色。

当前目录有 549 条可选分支，使用 404 个不同短标记。两把小提琴与中提琴各适用 539 条，大提琴增加 10 条专用特效。目录包括短／长音、连奏／滑奏、Ricochet、录制力度、速度选择、混合和序列等结构。分支与独立采样不是一一对应关系。

选中普通音符、和弦或休止符即可插入；选中已有谱表文字可替换。一次插入或替换作为一个撤销步骤处理，保存后重开可按有效绑定精确预选。选择器会核对目标位置的实际乐器，例如大提琴专用特效不能误写到小提琴谱表。

手工把可见文字改为 `pizz.` 或 `arco` 并提交后，旧精确绑定不再覆盖这个新命令。高级变体通常应从选择器选择；只输入一个看起来相同的短名不足以还原其全部含义。

### 对动态变化作有依据的平滑

Synchron Smooth Bridge 提供音源原始参考音频，Host Dynamics Smoother 则位于同一乐器轨的第一项效果器。效果器比较参考与接收到的音频，只有确认它们能由同一个宿主增益解释时，才平滑增益过渡。

平滑时间可在 0.5–100 ms 之间设置，默认 20 ms。原四重奏设置依次为一提 50 ms、二提 10 ms、中提 10 ms、大提 15 ms。稳定增益段保留输入样本；增益发生变化时使用连续过渡。较长时间会让动态变化响应更缓，应按乐句和声部试听调整。

这个机制处理的是音量增益变化，不会自动替音源选择力度层、驱动音色交叉渐变或修复所有采样音头。若参考缺失、不匹配或当前布局不适用，效果器会旁通。它与本项目桥接器配套，不能作为任意 VST 音源的通用动态修复器。

### 播放与原生导出使用相同的准备入口

选择新路线时，适配层检查当前播放器状态，增量启用它所需要的采样叶，而不是在一开始盲目启用全部目录。播放或导出会等待这一准备过程，用户无需先实时播放一遍来“预热”再导出。

删除奏法标记不会立刻卸载已经启用的采样，长期试用多种音色仍会增加内存占用，保存工程也可能保留扩大的启用集合。当前加载完成判断使用状态检查和进程活动观察，并不是厂商提供的统一 sample-ready 信号；不同机器、冷缓存和播放器版本仍需要验证。

Smooth Bridge 同时使音频块的处理模式与播放器成功接受的设置保持一致，用于衔接实时和离线工作。较早的 Offline Bridge Fix 保留给引用旧插件类的工程；新 Synchron 工作流使用 Smooth Bridge 与 Smoother 组合。

## 常见使用场景

### 我只想用其他 VST3 音源写谱

下载完整 Windows 包，按包内说明运行，将自己的插件目录加入宿主搜索路径，再为乐器选择音源。普通音符播放和音频导出沿用 VST3 宿主工作流，无需安装 VSL 产品，也不需要给这些音源套上 Synchron 桥接器。

如果希望 `pizz.`、断奏或连奏等进一步切换该音库的具体音色，需要为它建立匹配的表达映射。先核对插件的切换键和 CC 规则，再以短测试谱验证；不要直接将 Synchron 的键位表套到其他厂商音库。

### 我使用 Synchron Solo Strings，希望写完就能听见对应奏法

完整 Windows 包已经包含三款配套插件、映射与选择器，无需另下插件包。用户自行安装和授权播放器与音库，在每个声部选择独立的 Smooth Bridge 实例，载入对应的 Velocity 工厂预设，并把 Smoother 放到首个效果器位置。

先检查几个长音上的 `p → f → p`、一次 `pizz. → arco` 和连奏／断奏，再使用选择器加入更具体的变体。需要严格节奏的震音、颤音或抛弓音型时，要核对实际音高、音数和时值；选择一个录制片段不等于自动得到任意指定的演奏节奏。

### 我希望复用或继续开发

仓库保存官方 4.7.7 固定基线、完整改写补丁、源码还原脚本、配套插件源码与回归测试支持。开发者可以先还原已有版本，再扩展目标音库映射或宿主行为。源码路径、构建依赖和第三方声明分别见 [MuseScore 构建说明](BUILD-MUSESCORE.md)、[插件构建说明](BUILD-PLUGINS.md) 和 [第三方声明](../THIRD_PARTY_NOTICES.md)。

## 保存、兼容性与实际验证范围

新增精确绑定保存在本定制版的 MSCZ／MSCX 中。MusicXML 不保存这些字段，旧官方 MuseScore 重存也可能丢失绑定；PDF 上只有可见文字，不能完整表达重名路线的选择。需要继续编辑的作品应保留定制版源文件。

当前提供 Windows x64 包。新打包宿主已完成 MS Basic 的开谱与 PDF／WAV 导出检查。启动时可能出现“无法加载 MuseSounds”的提示；本次尚未确认 MuseSounds 兼容性。其他普通 VST3 音源没有逐一测试。

Synchron 已有验证使用 core 1.3.0.3022 与匹配的 Solo Strings 预设。其他音源可以使用宿主，但不据此宣称其所有功能已完成专项适配；跨平台也尚未验证。

代表组曾覆盖 27 个不同路线 ID，其中 23 个是高级目录分支，并有回放、原生 WAV 和听感记录。549 条目录并未逐一试听；1,088 个原生遍历用例是目录和选择状态检查，不是 1,088 次音乐试听。各历史组还使用过不同阶段的二进制，具体范围见 [验证说明](VALIDATION.md)。

仍需留意的音乐边界包括：单一音源实例上的同时声部不能独立要求互相冲突的音色；混合／XF 分支不会自动生成连续 CC 扫描；录制 Ricochet a1–a4 不承诺固定反弹次数；录制力度或固定速度片段不能保证适应任意曲速。当前配置也没有接通专用弱音器、sul ponticello 或 sul tasto 采样。

**English summary:** This project connects notation semantics to configurable VST3 articulation commands inside MuseScore's native playback/export chain. Upstream MuseScore already supplies VST3 hosting. The generic changes support matching key-switch maps with optional discrete MIDI CC values; the bundled detailed selector, sample preparation, and bridge/smoother plugins are Synchron-specific. Prebuilt Windows packages let end users work without compiling, while tagged source and build/test materials remain available for developers. Compatibility and musical validation are bounded by the tested instruments, presets, versions, and routes.
